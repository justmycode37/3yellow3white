# Scene-generation speed experiment

Historical experiment record. Its prompts, style criteria, and test counts describe that experiment; current production rules are in [instruction architecture](instruction-architecture.md).

User approved RNA transcription, binary search, and the derivative of x². Freeze two-scene explanations, plans, narration packets, audio and hashes before comparisons. Use current production authoring instructions, validation and renderer. Keep the running user server unchanged.

Compare baseline Astra/high/text against validated-reference output, explicit terminal submission, another locally available model, and author-only library documentation. Change one factor at a time before combining promising candidates. Run all three topics for each screened variant; retain failed results too. Measure wall time, provider turns, token/cache usage, validation count/time and prompt/output sizes. Scene 2 uses each candidate's actual final frame, so continuity is tested. Repeat finalists against baseline; exploratory timings alone do not establish stable speedups.

All variants retain exactly the same narration and teaching obligations. Hard gates: compilation, audio identity, duration, plan carry/cleanup, and completed generation. Visual review separately judges reasoning, legibility, style and timing. Reject any clear downgrade; retain uncertain candidates as unverified, never call them lossless. Save sources, packets, audio and real-renderer replay gallery. Independent reviewer inspects actual rendered samples before any promotion. No production default changes until evidence supports them.

Implementation: optional runtime output protocols and safe metrics; deterministic reference extraction; fixed fixture/harness; browser replay gallery; paired runs; review and report. Tests cover protocol validation/error/abort behavior, reference extraction and fixture validity. Experiments live under ignored data/scene-speed; report records their provenance and limitations.
